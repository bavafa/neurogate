# synth/: lint, synthesis, gate-level simulation and estimates

Everything here is simulation or an estimate. Nothing ran on hardware. Synthesis
here is Yosys plus ABC with no place and route; the library is the Nangate Open
Cell Library (45 nm, typical corner), a teaching library, not a foundry flow.

| Command | What it does | Label |
|---|---|---|
| `make lint` | Verilator `--lint-only -Wall` on every RTL file as the top; lists the waivers | checked |
| `make synth` | Yosys maps the whole chip to Nangate45; writes the gate netlist and reports | *synthesized (estimate)* |
| `make gls` | Runs the 120-frame smoke vectors, then the 480-frame bad-packet set, through the netlist with Icarus; compares with the Python models | *simulated* |
| `make synth-xilinx` | Yosys `synth_xilinx` (Artix-7 count) | *estimate*, not Vivado |
| `make sta` | OpenSTA timing of the Nangate45 netlist at the SPEC clocks (needs `make synth`) | *synthesized (estimate)*: typical corner, ideal clocks, no place and route |
| `make test` | includes `tb/test_neurogate_top_throughput.py` (cycles per packet) | *simulated* |

Timing numbers are in the "Timing" section below and in `reports/sta*.txt`. They are
estimates: typical corner, ideal clocks (no clock tree), no wires unless stated, no
place and route.

## Files

- `synth_nangate45.ys`, `run_synth.sh`: the synthesis script and its runner.
- `synth_artix7.ys`: the Artix-7 script.
- `abc.constr`: input driver (BUF_X1) and output load (3 fF) that the logic mapper assumes when it buffers and sizes gates.
- `neurogate_top.sdc`: timing constraints (clocks, clock-crossing limits, reset, pins), each explained in a comment.
- `sta.tcl`, `run_sta.sh`: the OpenSTA script and its runner.
- `gen_cell_models.sh`: makes Verilog models of the library cells (from the fetched liberty file) for gate-level simulation. Output is not committed.
- `reports/cells.txt` (cells and area), `reports/check.txt` (Yosys `check -assert`), `reports/artix7_cells.txt`, `reports/gls.log`, `reports/gls_bad.log`, `reports/sta.txt` (timing, no wire load), `reports/sta_wireload.txt` (timing with the library's default wire-load model), `reports/sta_before.txt` (timing of the earlier area-only netlist, kept for comparison): committed reports. The full Yosys logs and the netlist (`out/`) are regenerated by the make targets and not committed (the log is 0.7 MB, the netlist 2 MB).

## Lint

`make lint` prints no warning on all 11 RTL files. Four inline waivers exist, each with its reason in a comment in the file:

| File | Check waived | Reason |
|---|---|---|
| `rtl/axil_regs.sv` | UNUSEDSIGNAL (address and write-data bit groups) | no register has more than one writable byte; the other bits are intentionally unused |
| `rtl/neurogate_top.sv` (entry debug wires) | UNUSEDSIGNAL | the entry only carries kind = drop; the drop reason is debug detail |
| `rtl/neurogate_top.sv` (FIFO constant sideband) | UNUSEDSIGNAL | constant `tkeep`/`tlast`/`tuser` come back out of the FIFO unchanged; nothing needs them |
| `rtl/reset_sync.sv` | SYNCASYNCNET | the reset output is used as an asynchronous reset by the FIFO (so both sides clear together) and as a synchronous reset elsewhere; release is synchronous to the clock either way |

## Synthesis result (*synthesized (estimate)*, Nangate45 typical corner)

From `reports/cells.txt`, whole chip flattened. Since the timing session the logic mapper
works to a 5 ns delay target and adds buffers (see "Timing"); that added 1,325 cells
(1,143 of them `BUF_X1`) and about 3% area. The flip-flops did not change.

| Item | Value |
|---|---|
| Cells | 18,907 (17,582 before the timing session) |
| Area | 34,866 um^2, sequential cells 16,975 um^2, 48.7% (before the timing session: 33,821 um^2, 50.2%) |
| Flip-flops | 3,746 (DFF_X1 3,702, DFFR_X1 42, DFFS_X1 2) |
| Latch cells | 0 |
| Yosys `check -assert` | 0 problems |

The flip-flop count is high because the library has no memory macros: the asynchronous
FIFO storage, the input queue, the feature history and the weight ROMs are all built from
gates and flip-flops. The 11 memories Yosys found (neural-net buffers `x`, `h`, `z`, four
weight/bias ROMs, FIFO storage, input queue, feature history `ring` and `bcnt`) are all
intended. This is an area estimate without place and route, not a layout result.

## Gate-level simulation (*simulated*)

`make gls`: the same 120 generated frames, same seed handling and same checks as the RTL
smoke test (`tb/neurogate_top_checks.py`) run on the netlist plus the cell models in Icarus.
Result: 110 of 110 expected result beats, 0 mismatches against the Python models, 0 protocol
errors, all counters read over the register bus equal to the model, soft reset clears them.
These are the same numbers as the RTL run, so on these vectors the netlist outputs equal the RTL
outputs. The cells have no delays, so this checks function, not timing. It was re-run on the
buffered netlist of the timing session with the same result.

The bad-packet set (`python3 tb/gls_run.py bad`, part of `make gls`; log `reports/gls_bad.log`)
is the same 480 frames and the same checks as the RTL bad-packet test: truncated frames of
every length, wrong EtherTypes, broken IP headers, error flags, random bytes and a 1514-byte
frame, mixed with good frames, with random pauses on the result stream. Result on the
netlist, seed 12345: 176 of 176 expected result beats (304 frames dropped as the model
predicts), 0 mismatches, 0 protocol errors, every counter equal to the model, no overflow.
Only these two sets were run on the netlist; the larger RTL tests (9,000-frame traffic,
overflow, resets) were not repeated on it. No fault was planted in the netlist for the
bad-packet run; it uses the same check code that failed on planted RTL faults, and the smoke
run's fault demonstration is the one in `reports/gls_fault.log`.
Check that the test can fail: 36 of 386 `AND2_X1` cells in the netlist were changed to
`OR2_X1`; the run failed, then the netlist was restored. The output of that run is kept in
`reports/gls_fault.log` (an earlier manual run of the same idea failed with "AXI-Lite write
never accepted"; the kept log shows the failure of the repeat run).

## Throughput (*simulated*, RTL)

`tb/test_neurogate_top_throughput.py`: 14 classified frames back to back, result stream always
ready, no frame lost. With a backlog the core takes 179 core clocks between result beats (min,
mean and max all 179). At `core_clk` 200 MHz (the SPEC target; timing is not checked) that is
about 1.117 million packets per second, limited by the neural-network core, not by the input
bus. The first frame's delay from last input beat to result beat is 187 core clocks. Input
of the 14 frames took 42.0 net clocks per frame on average (mean frame 321 bytes), so the
input side is faster than the core and the async FIFO fills under a burst. Synthetic traffic
only; this is a cycle count times the SPEC clock, a simulated estimate.

## Timing (*synthesized (estimate)*, OpenSTA, Nangate45 typical corner)

`make sta` runs OpenSTA (an open-source static timing analyzer: it adds up cell delays along
every path between flip-flops, without simulation) on the netlist from `make synth`.
The constraints in `neurogate_top.sdc` are:

- **Clocks** at the SPEC targets: network clock 156.25 MHz (6.4 ns), core clock 200 MHz
  (5.0 ns). The AXI-Lite register bus has no clock of its own; it runs on the core clock.
  Clocks are ideal: no clock tree delay, skew, jitter or safety margin.
- **Between the two clocks**: they are unrelated, so the default check (closest pair of
  edges, here 0.2 ns) is replaced. Every crossing path must take at most 5.0 ns (one core
  clock period). For the Gray-coded FIFO pointers this keeps the bits of one pointer
  arriving close together, so the other side reads either the old or the new value. The FIFO
  storage is read at least two core clocks after it was written, so 5.0 ns is on the safe
  side there. Hold is not checked between the clocks: there is no fixed edge to measure
  against, and that case is what the two-flop synchronizers are for. The clock-crossing
  check (`make cdc-check`) shows the FIFO paths are the only ones that cross.
- **External reset** pin: not timed (it is asynchronous by design and goes only to the
  reset synchronizers). The synchronizer outputs are timed like any flop output, including
  recovery and removal at the flip-flops with an asynchronous reset.
- **Pins**: guessed, as SPEC gives no outside timing. Outside logic uses 20% of the clock
  period on each side; inputs are driven by a `BUF_X1`; outputs drive 3 fF.

### Before and after (estimate, no wire load)

The first run used the netlist of the previous session (area-only mapping). The core clock
failed setup by 6.19 ns. The cause was not deep logic: one bit of the FIFO read address drove
573 gate inputs of the storage read multiplexer, and an inverter after it drove 419 more. With
no buffers, those two cells took 9.85 ns. The fix was in synthesis, not in the RTL: the
logic mapper (ABC) now gets a 5 ns delay target and adds buffers on such nets and resizes
gates (`synth_nangate45.ys`). The logic is unchanged; only the way it is built from cells
changes. No pipeline stage was needed, so latency is unchanged.

| Check (worst slack, ns; positive = met) | Before (area-only netlist) | After (delay-target netlist) |
|---|---|---|
| Core clock, setup, flop to flop | **-6.186 (fails)** | 2.649 |
| Core clock, hold, flop to flop | 0.080 | 0.080 |
| Network clock, setup, flop to flop | 1.802 | 4.694 |
| Network clock, hold, flop to flop | 0.080 | 0.080 |
| Crossing network to core (limit 5.0 ns) | 4.510 | 4.627 |
| Crossing core to network (limit 5.0 ns) | 4.856 | 4.856 |
| Inputs / outputs, core clock | 2.205 / 2.931 | 2.810 / 2.931 |
| Inputs / outputs, network clock | 4.433 / 4.946 | 4.814 / 4.946 |
| Recovery at reset pins (core / network) | 3.898 / 5.385 | 4.861 / 6.261 |
| **Removal at reset pins (core / network)** | **-0.261 / -0.247 (fail)** | **-0.108 / -0.108 (fail)** |
| Total negative setup slack | -465.721 | 0.000 |
| Library design-rule violations (max slew / max capacitance) | 1,319 / 129 | 0 / 2 |

With the library's default wire-load model (a rough guess of wire capacitance from fanout,
`reports/sta_wireload.txt`): core clock setup 2.405, network clock setup 4.547, removal
-0.115 on both clocks. So the setup result holds with that rough wire estimate.

Highest clock frequency this suggests (estimate, ideal clocks, no wires): core clock path
2.35 ns of logic and setup time (5.0 - 2.649), network clock 1.71 ns (6.4 - 4.694).
These are not claims about a real chip.

### Critical paths (after)

- **Core clock** (slack 2.649 ns): from the neural-net core's output register (entry kind and
  the three scores) through the decision unit's margin arithmetic (top score minus second
  score, saturate, compare with the threshold) to the decision unit's "low confidence" output
  flop. 62 cells deep (including buffers); the path starts at the entry-kind bit of that register.
- **Network clock** (slack 4.694 ns): from the Ethernet parser's output register (byte-valid
  bits) through the IPv4/TCP/UDP parser's byte-position logic to its IPv4 length field (38 cells deep).

### Open problem: removal at the FIFO reset pins (not fixed)

40 flip-flops in the asynchronous FIFO use an asynchronous reset (or set) pin, driven by the
reset synchronizer of their own clock. The synchronizer's flop changes 0.18 ns after the
clock edge, but the library wants the reset to release at least 0.288 ns after the edge
(the "removal" time), so the check fails by 0.108 ns. If it happened in silicon, a FIFO flop
could leave reset one clock earlier than the others. This is the kind of violation a place
and route flow fixes by adding small delay cells on that net after the clock tree is
built (hold fixing); this project stops before place and route, so it is reported, not
fixed. Because of it `make sta` exits 1. A pipeline stage would not help: removal does not
depend on the clock period.

### What this timing does not cover

No clock tree, no real wires (only an optional wire-load guess), one corner (typical, 1.1 V,
25 C), no on-chip variation, no signal integrity, no power. Two nets still exceed the
library's maximum capacitance after buffering (`reports/sta.txt`, last section), so the
delays on those two nets are extrapolated from the library tables.
