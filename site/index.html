NeuroGate: an AI-built packet-classification IP block, verified in simulation.

Built by Sam Bavafa (M.Sc. Electrical Engineering), in a weekend (Nov 13 to 15, 2026), using a multi-agent AI flow.

Sam is not a practising RTL designer. This project shows AI-assisted engineering on a packet-processing block.

Everything here is simulation or a tool estimate. Nothing ran on FPGA or silicon. All traffic is synthetic.

Follow one packet Repo Evidence

Why this problem

Classify each packet in the data path with a small neural network, instead of in software.

Putting small ML models in the packet path is an active direction for SmartNICs and DPUs. NeuroGate is a small working example of that idea. It is not a new invention and it does not claim to compete with production designs.

The model is small on purpose: 8 inputs, 16 hidden units, 3 outputs, int8 weights. The block labels each packet as normal, port scan or SYN flood and reports a confidence margin. The point of the project is the whole path at small scale: AXI-Stream input, header parsing, feature extraction over a sliding window, a clock-domain crossing, fixed-point inference, flow control, counters and an AXI-Lite register interface. All of it is checked against a Python reference model.

How it was built with AI

Four roles, one human. The AI agents wrote the RTL and the tests. Sam directed the work and approved every gate.

    Input analysis

    Three synthetic traffic classes from one generator, with overlap on purpose.

    The generator (model/traffic_gen.py, Scapy, fixed seeds) builds ordered scenarios. Each scenario is one stream of one class.

    • Normal: TCP data and ACK, TCP connection starts (a normal SYN, on purpose), FIN and RST, UDP, ICMP, ARP, VLAN-tagged TCP, non-first IP fragments, truncated frames and frames with tuser set.
    • Port scan: bare SYNs from one source to one target, sequential or random destination ports, varied pacing.
    • SYN flood: bare SYNs to one target port (80, 443 or 8080), from one or many sources.
    • Attack scenarios mix in 0 to 50% normal background packets, chosen per scenario, so the classes overlap.
    • The split is by scenario and generator seed. The test split uses a master seed training never saw.

    Feature distributions per class

    Each panel is one of the 8 int8 features on the 8,347 classified test packets. Binary features show the share of packets with the flag set. Other features show the share of the class in 8 bins of width 16 over 0 to 127.

    Why 653 of 9,000 frames were dropped

    The parser drops frames it cannot or does not parse (spec section 4). Every dropped frame in this split is a normal-class frame; no attack frame is dropped. Dropped frames never reach the network and never enter the feature window.

    What a production flow would add

    • Commercial CDC analysis (this project has a structural script and a written review, not a sign-off).
    • Logical equivalence checking (LEC) between RTL and netlist. Here, gate-level simulation covered two vector sets only.
    • Coverage closure with a coverage-driven verification environment (functional and code coverage).
    • Place and route, with clock tree, real wires and corners. This is where the reset-removal miss would be fixed.
    • An FPGA run and, later, silicon-oriented signoff. Neither exists here.

    Implementation

    Area, timing and throughput from Yosys and OpenSTA reports, plus a cycle count from simulation.

    estimate Yosys and ABC with the Nangate45 teaching library, typical corner, ideal clocks, no wires, no place and route. These numbers say nothing about a real device.

    Timing (OpenSTA, positive slack = met)

    The reset-removal check fails by 0.108 ns on both clocks and is shown as it is in the report. The cause is 40 flip-flops with an asynchronous reset pin whose synchronizer output changes 0.18 ns after the clock edge, while the library wants at least 0.288 ns. This is normally fixed with delay cells after clock-tree build, which this project does not have. make sta exits non-zero because of it. The owner accepted this as "reported, not fixed" at Gate M4.

    The first mapping failed core-clock setup by 6.186 ns because one FIFO read-address bit drove hundreds of gate inputs. The fix was a delay target for the logic mapper, which added buffers. The logic and latency did not change.

    estimate Sources: sta.txt, sta_before.txt, sta_wireload.txt, synth/README.md.

    What happens when the core falls behind

    • The input is not stalled because the asynchronous FIFO is full. s_axis_tready goes low only when the 4-slot input queue is full (spec section 2, neurogate_top.sv header).
    • When an entry is ready and the FIFO is full, feature_builder throws the entry away and adds 1 to a 16-bit pending-overflow count. The next entry that gets through carries the count. An overflow-only entry carries it if no packet is waiting.
    • The count reaches the PKT_OVERFLOW register. Every frame lands in exactly one counter once the pipeline has drained. The pending count saturates at 65,535, which the spec states as a known limit.
    • Frames lost to overflow still enter the feature window, so features depend only on the packet stream, not on timing (D-004).
    • An overflow test exists in the stress suite (test_overflow). No overflow behaviour is shown in a committed log here; see STATUS.md.

    Sources: SPEC.md sections 2 and 8.1, rtl/feature_builder.sv.

    Limitations

    From the README, with the same meaning.

    • Synthetic data. All traffic comes from this repo's generator. Real traffic is messier. Accuracy here is not real-world accuracy. Nothing was tested on real captures.
    • Simulation only. Nothing ran on an FPGA or in silicon. Throughput is a cycle count from simulation times the target clock. It is a simulated estimate, not a measured line rate.
    • Clock crossings: structural check plus review, no formal proof. A script checks that every crossing is one of the allowed kinds, and the builder wrote a review of each. This is not a commercial CDC tool. Simulation cannot show metastability.
    • Timing without place and route. Ideal clocks, no wires beyond one rough guess, one typical condition, a guessed 20% budget for outside logic. Setup is met on both clocks (estimate). The reset-release miss of 0.108 ns is reported as not done.
    • Gate-level simulation is partial. The netlist ran a 120-frame smoke set and a 480-frame bad-packet set. Longer traffic, overflow and reset tests were not repeated on it. The gate models have no delays, so it checks function, not timing.
    • Not done. No FPGA or silicon run, no Vivado result, no power estimate, no formal proofs, no real-world traffic, no manufacturing flow.
    • Small design on purpose. IPv4 with TCP or UDP and at most one VLAN tag. Everything else is counted as dropped.
    • Features are approximations. Ports are hashed into 64 buckets, so two ports can share one and the count can be too low. Only SYN without ACK is counted as a connection request.
