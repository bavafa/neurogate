A small hardware block that labels network packets

The problem. Network attacks such as port scans and SYN floods are commonly detected in software, after packets have been received and queued. A port scan is one machine probing many ports to find open ones. A SYN flood is a burst of connection requests that are never finished, meant to overload a server. SYN, short for synchronize, is the first message of a connection. Putting small ML models in the packet path is an active direction for SmartNICs and DPUs.

The approach. NeuroGate is a hardware design, written in SystemVerilog (a language for describing digital circuits), that reads each network packet and labels it normal, port scan or SYN flood. A tiny neural network with 8-bit integer weights makes the call from eight numbers about the packet and the recent traffic. This page collects the results. All of them come from simulation on synthetic data.

Scope: everything here is simulation or a tool estimate. Nothing ran on FPGA or silicon. All traffic is synthetic.

What was built

The model is small on purpose: 8 inputs, 16 hidden units, 3 outputs, int8 weights. The block labels each packet as normal, port scan or SYN flood and reports a confidence margin. The point of the project is the whole path at small scale: AXI-Stream input, header parsing, feature extraction over a sliding window, a clock-domain crossing, fixed-point inference, flow control, counters and an AXI-Lite register interface. All of it is checked against a Python reference model.

How it was built with AI

Built with a multi-agent flow. Claude Code builds each milestone, OpenAI Codex reviews it, and the engineer sets the scope and design decisions and approves each milestone before the next one starts.

    Input analysis

    Three synthetic traffic classes from one generator, with overlap on purpose.

    The generator (model/traffic_gen.py, Scapy, fixed seeds) builds ordered scenarios. Each scenario is one stream of one class.

    • Normal: TCP data and ACK, TCP connection starts (a normal SYN, on purpose), FIN and RST, UDP, ICMP, ARP, VLAN-tagged TCP, non-first IP fragments, truncated frames and frames with tuser set.
    • Port scan: bare SYNs from one source to one target, sequential or random destination ports, varied pacing.
    • SYN flood: bare SYNs to one target port (80, 443 or 8080), from one or many sources.
    • Attack scenarios mix in 0 to 50% normal background packets, chosen per scenario, so the classes overlap.
    • The split is by scenario and generator seed. The test split uses a master seed training never saw.

    Why 653 of 9,000 frames were dropped

    The parser drops frames it cannot or does not parse (spec section 4). Every dropped frame in this split is a normal-class frame; no attack frame is dropped. Dropped frames never reach the network and never enter the feature window.

    Confidence margin against measured accuracy

    Confidence is a logit margin (top score minus second score, shifted right by 8, capped at 127). It is not a probability. The default threshold of 13 was chosen on a validation split with one rule: the smallest threshold for which kept packets are at least 98% correct.     What a production flow would add

    • Commercial CDC analysis (here: a structural script and a written review).
    • Logical equivalence checking (LEC) between RTL and netlist. Here, gate-level simulation covers two vector sets.
    • Coverage closure with a coverage-driven verification environment (functional and code coverage).
    • Place and route, with clock tree, real wires and corners. This is where the reset-removal miss would be fixed.
    • An FPGA run and, later, silicon-oriented signoff.

    Timing (OpenSTA, positive slack = met)

    Reset removal is -0.108 ns on both clocks, shown here as in the report. Cause: 40 flip-flops with an asynchronous reset pin, whose synchronizer output changes 0.18 ns after the clock edge while the library wants at least 0.288 ns. This is normally closed with delay cells after clock-tree build, which is a place-and-route step. make sta exits non-zero for this reason. Accepted as "reported, not fixed" at Gate M4.

    The first mapping missed core-clock setup by 6.186 ns because one FIFO read-address bit drove hundreds of gate inputs. A delay target for the logic mapper added buffers and closed it, with no change to the logic or the latency.

    What happens when the core falls behind

    • The input is not stalled because the asynchronous FIFO is full. s_axis_tready goes low only when the 4-slot input queue is full (spec section 2, neurogate_top.sv header).
    • When an entry is ready and the FIFO is full, feature_builder throws the entry away and adds 1 to a 16-bit pending-overflow count. The next entry that gets through carries the count. An overflow-only entry carries it if no packet is waiting.
    • The count reaches the PKT_OVERFLOW register. Every frame lands in exactly one counter once the pipeline has drained. The pending count saturates at 65,535, which the spec states as a known limit.
    • Frames lost to overflow still enter the feature window, so features depend only on the packet stream, not on timing (D-004).
    • An overflow test is part of the stress suite (test_overflow).

    Sources: SPEC.md sections 2 and 8.1, rtl/feature_builder.sv.

    Scope and limits

    What the project covers and where it stops.

    • Synthetic data. All traffic comes from this repo's generator, so accuracy figures are not real-world accuracy. No real captures were used.
    • Simulation and estimates. No FPGA or silicon run. Throughput is a cycle count from simulation times the target clock: a simulated estimate, not a measured line rate.
    • Clock crossings. A structural script plus a written review of each crossing. It is not a commercial CDC tool or a proof, and simulation does not show metastability.
    • Timing. Ideal clocks, no place and route, one typical condition, a guessed 20% budget for outside logic. Setup is met on both clocks (estimate). Reset release is -0.108 ns, reported as is.
    • Gate-level simulation. The netlist ran a 120-frame smoke set and a 480-frame bad-packet set. The gate models have no delays, so it checks function, not timing.
    • Out of scope. FPGA or silicon run, Vivado result, power estimate, formal proofs, real-world traffic, manufacturing flow.
    • Design scope. IPv4 with TCP or UDP and at most one VLAN tag. Everything else is counted as dropped.
    • Feature approximations. Ports are hashed into 64 buckets, so two ports can share one and the count can read low. Only SYN without ACK counts as a connection request.

    Source: README.md, Limitations.
